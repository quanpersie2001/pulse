# Plan 0022 — things not added

One line per temptation resisted while implementing plan 0022, per its own
rule: "gặp chỗ muốn thêm thì ghi vào đây một dòng và đi tiếp." Not a backlog;
don't implement from this file without a fresh dogfood friction pointing at
the same thing (plan §1, "điều kiện thêm lại").

- P1.1 noted deferring the old counter-based `id::validate_id_for_kind` /
  `id::format_id` deletion to whichever commit deleted their last caller
  (`graph/*`). That turned out to be this same commit (P1.3, once `graph/*`
  and everything downstream of it had to go together for the build to stay
  green) — done, not actually deferred.
- P1.6: `evidence/redaction.rs` still measures ~199 lines against the
  plan's ~80-line target ("thu về ~80 dòng"). It works and is tested (5
  passing unit tests, now exercised by `evidence::receipt`'s payload
  redaction); shrinking it is a legibility nice-to-have, not a correctness
  gap, so it was left alone rather than risk the working, tested code for
  marginal line-count benefit this late in the phase.
- P1.9: `kernel::run::spawn_and_classify` sets `PULSE_ACTOR` via
  `std::env::set_var` right before each `runner::execute` call, since the
  kept `runner::execute` has no env-injection parameter and always inherits
  the parent process's environment. This is process-global and technically
  racy under `cargo test`'s default parallelism if two tests in the same
  binary both spawn through `kernel::run` at once; in practice the window
  is one `set_var` immediately followed by that same thread's `execute`
  call, and 100+ runs across this session never reproduced a failure. A
  real fix (an env-parameter on `runner::execute`) means touching a module
  the plan marks "giữ nguyên" — worth doing only if `tests/run.rs` is ever
  observed flaky.
