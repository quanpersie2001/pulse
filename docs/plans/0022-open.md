# Plan 0022 — things not added

One line per temptation resisted while implementing plan 0022, per its own
rule: "gặp chỗ muốn thêm thì ghi vào đây một dòng và đi tiếp." Not a backlog;
don't implement from this file without a fresh dogfood friction pointing at
the same thing (plan §1, "điều kiện thêm lại").

- P1.1 noted deferring the old counter-based `id::validate_id_for_kind` /
  `id::format_id` deletion to whichever commit deleted their last caller
  (`graph/*`). That turned out to be this same commit (P1.3, once `graph/*`
  and everything downstream of it had to go together for the build to stay
  green) — done, not actually deferred.
- P1.6: `evidence/redaction.rs` still measures ~199 lines against the
  plan's ~80-line target ("thu về ~80 dòng"). It works and is tested (5
  passing unit tests, now exercised by `evidence::receipt`'s payload
  redaction); shrinking it is a legibility nice-to-have, not a correctness
  gap, so it was left alone rather than risk the working, tested code for
  marginal line-count benefit this late in the phase.
- P1.9: `kernel::run::spawn_and_classify` sets `PULSE_ACTOR` via
  `std::env::set_var` right before each `runner::execute` call — done at F6
  (P1.12): `runner::execute` gained an `env: &[(&str, String)]` parameter
  applied per-child via `Command::envs`, and both `spawn_and_classify` and
  `kernel::run::run_lane` now pass `PULSE_ACTOR` through it instead of
  mutating the process-global environment.
- P1.12 review carried two items into Phase 2A — done at A1: `run_lane`'s
  story-scope profile check no longer needs `--force` to get past a Story
  missing `surface`/`risk` (that data gap now always raises `profile_missing`
  with a hint pointing at `pulse work update ... --set surface=... --set
  risk=...`, whether or not `--force` was passed; `--force` still only
  bypasses a resolved profile not listing the lane, same as for a Ticket);
  and `src/cli/events.rs`'s docstring dropped the stale `|compact` (that
  command was removed in F3, P1.12).
- A7: `src/` is 13089 lines after Phase 2A, 3089 over the < 10000 v3.0
  target (the largest single file is `src/kernel/completion.rs` at 1210,
  then `src/storage/transaction.rs` at 855 — both file-fate "giữ
  nguyên"). Per A7's instruction, not cutting anything this session; the
  question to decide in Phase 3 with real dogfood data in hand:
  `storage/transaction.rs` (855 lines) còn cần cho một `issues.jsonl`
  không? Checked, not just asked, and the answer is more pointed than
  the question assumed: `store::issues::mutate` never calls it — the
  store's read-validate-write goes through `storage::atomic_write`
  (single-target `atomic::atomic_replace`) — and grepping `src/` and
  `tests/` for every one of `transaction.rs`'s public multi-target
  functions (`prepare_multi_target_transaction`,
  `commit_prepared_multi_target_transaction`,
  `recover_prepared_transactions`, ...) finds exactly one caller
  outside `transaction.rs`'s own tests: `evidence/artifact.rs` (255
  lines, `put_artifact`/`show_artifact`/`verify_artifact`). And
  `evidence/artifact.rs` itself has **zero** callers anywhere in `src/`
  or `tests/` beyond its own re-export in `evidence/mod.rs` — no `cli::`
  module wires it up (there is no `pulse evidence` command; plan §6's
  command table confirms this is deliberate: "Không có: ... `evidence
  *`"), and `kernel::lane`'s own artifact hashing
  (`evidence::receipt::record_receipt`, plan §5.1's "một họ receipt")
  hashes artifact bytes inline with `canonical_json::hash_bytes`,
  bypassing `evidence::artifact` entirely. So today, in the tree this
  session leaves behind, `storage/transaction.rs`'s multi-target
  machinery has no live caller reachable from the CLI at all — its only
  caller is itself-orphaned v2 leftover code. Not deleted this
  session (that is a bigger, more deliberate cut than A7's line-count
  note is meant to authorize, and plan §1's "điều kiện thêm lại" rule
  cuts both ways — a real removal deserves its own commit, not a
  footnote); flagged here for Phase 3 to size properly: `evidence/
  artifact.rs`'s only caller in `src/` is its own `evidence/mod.rs`
  re-export, and `transaction.rs`'s single-target functions
  (`prepare_transaction`/`commit_prepared_transaction`/
  `persist_intent`/`complete_and_cleanup_intent`) have no caller
  anywhere either, production or test, beyond `tests/storage/
  storage_primitives.rs` exercising the module directly — so
  `transaction.rs`'s entire *production* caller graph, single-target
  and multi-target both, is the one orphaned file. Cutting
  `evidence/artifact.rs` (255 lines) plus `transaction.rs` (855) plus
  whatever of `tests/storage.rs`'s 23 cases exist only to cover them
  would be a meaningful, low-risk chunk of the 3089-line gap to the
  v3.0 target — "low-risk" because nothing in the CLI-reachable graph
  currently depends on any of it.
